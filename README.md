# Bowling Kata

Robert C. Martin이 만든 TDD 연습용 kata. 실제 볼링 게임을 만드는 것이 아니라, **볼링 점수를 계산하는 로직과 설계**를 TDD Cycle(RED → GREEN → REFACTOR/REVIEW)로 연습한다.

이 저장소는 AI 코딩 에이전트(Claude Code)와 함께 TDD를 수행하는 실습용 프로젝트다. 자세한 진행 방식은 `.claude/TDD/SKILL.md`의 `test-driven-development` 스킬을 따른다.

## 볼링 규칙

- 경기는 10개의 볼링 핀을 넘어뜨리는 게임이며, 총 **10 라운드(프레임)**로 진행된다.
- 각 라운드마다 최대 2번의 공을 굴릴 기회가 주어지고, 다음 라운드 시작 시 핀은 10개로 초기화된다.
- 10번째 라운드만 예외로 최대 **3번**까지 굴릴 수 있다.

### 기본 점수

| 결과 | 조건 | 점수 |
|---|---|---|
| 오픈 프레임 | 두 번 던져 10개 미만으로 쓰러뜨림 | 쓰러뜨린 핀 수의 합 |
| 스페어(Spare) | 두 번 던져 10개를 모두 쓰러뜨림 | 10 + 다음 1번 투구의 핀 수 |
| 스트라이크(Strike) | 첫 번째 투구에 10개를 모두 쓰러뜨림 | 10 + 다음 2번 투구의 핀 수 |

### 마지막 10번째 라운드 보너스

스페어나 스트라이크가 나오면 보너스 점수 계산을 위한 추가 투구 기회가 주어진다.

- 스페어인 경우: 보너스 투구 1회 추가 (총 3구)
- 스트라이크인 경우: 보너스 투구 2회 추가 (총 3구)
- 단, 이 보너스 투구 자체는 다시 스트라이크/스페어가 되어도 추가 기회를 주지 않는다.

### 예시

- `3, 2` → 이번 라운드 점수 = 3 + 2 = 5
- `2, /(8)` (스페어, 다음 투구가 3) → 이번 라운드 점수 = 2 + 8 + 3 = 13
- `X`(스트라이크, 다음 두 투구가 3, 5) → 이번 라운드 점수 = 10 + 3 + 5 = 18
- 퍼펙트 게임(12연속 스트라이크) → 총점 300

## TDD로 진행하는 방식

이 저장소는 human-in-the-loop RED → GREEN → REVIEW 사이클을 따른다 (자세한 내용은 `.claude/TDD/SKILL.md` 참고).

1. **RED**: 가장 단순한 요구사항부터 시작해 실패하는 테스트를 작성하고, 실제로 실패하는지 확인한다.
   - 예: 모든 투구가 거터(0핀)일 때 `score() == 0`
2. **GREEN**: 테스트를 통과시키는 최소한의 코드만 작성한다. 다음 사이클을 미리 구현하지 않는다.
3. **REVIEW**: 구현이 계획(Plan)의 범위를 벗어나지 않았는지 확인하고, 필요하면 리팩토링한다.

권장 사이클 순서: 거터 게임(전부 0) → 전부 1핀 → 스페어 → 스트라이크 → 퍼펙트 게임(모두 스트라이크) → 10번째 프레임 특수 규칙.

모든 테스트 함수는 `def test_한글...` 형식으로 작성한다 (예: `def test_거터_게임의_점수는_0이다():`).
